# Leaf Value Network — Implemented Design and Measured Behaviour

Date: 2026-11-14
Status: **implemented and wired**; exact-showdown remains the default safety net.

This note replaces the earlier "not implemented" design study. It documents what
actually shipped, why the runtime shape is what it is, and where the accuracy
limits come from.

## 1. What the engine needs at a leaf

At a depth-limited flop/turn exit, `solver_daemon/src/cfr.rs::showdown_values()`
needs, for every hand class `i` and opponent class `j`:

```
v_oop[i] = Σ_j reach_ip[j] * (equity[i][j] * net_pot - invested_oop)
v_ip[j]  = Σ_i reach_oop[i] * ((1 - equity[i][j]) * net_pot - invested_ip)
```

The exit evaluation is a **169-vector per player**, conditioned on the
node-local reach ranges. Exact `equity` is board-only and is computed once per
solve by `compute_equity()` (400 sampled runouts on the flop, all rivers on the
turn, exact on the river).

## 2. Model

`ml/models/leaf_value_net.py` (`LeafValueNet`):

| Piece | Size |
|---|---|
| Board features (`encode_board`) | 75 |
| OOP reach, normalised to sum 1 | 169 |
| IP reach, normalised to sum 1 | 169 |
| Node context (pot, invested, stack, ante, rake, folded) | 9 |
| **Input** | **422** |
| Trunk | 422 → 256 (GELU + LayerNorm) → 128 (GELU) |
| Heads | two 169-way sigmoid heads (`t_oop`, `t_ip`) |

`t_oop[i]` is class `i`'s share of the net pot against the opponent's
*normalised* range. Counterfactual values are rebuilt as

```
v_oop[i] = (t_oop[i] * net_pot - invested_oop) * reach_ip_mass
v_ip[j]  = (t_ip[j]  * net_pot - invested_ip)  * reach_oop_mass
```

so they are linear in the opponent's reach mass, which is the multilinearity CFR
requires.

## 3. Targets and data

Targets are exact, not a root aggregate:

```
t_oop[i] = (v_oop[i] / reach_ip_mass + invested_oop) / net_pot
t_ip[j]  = (v_ip[j]  / reach_oop_mass + invested_ip)  / net_pot
```

generated by the Rust solver with `GTO_LEAF_NET=off`.

| Dataset | Rows | Boards | Notes |
|---|---|---|---|
| `nl500_100bb_leaf_cfr.parquet` | 10,001 | 1,755 | one converged solve per board, 5–9 leaves each |
| `nl500_100bb_leaf_cfr_aug.parquet` | 26,325 | 1,755 | 3 reach perturbations per board (σ=0.7, 15% class pruning), 15 leaves each |
| **Combined** | **36,326** | **1,755** | train/val split by board (296 unseen boards) |

The perturbations exist because the unaugmented dataset only contains the
node-local reaches of one converged BTN/BB solve. CFR later visits skewed
reaches that were out of distribution, which is what drove the root-EV
conservation drift.

Training additionally builds convex mixes of two leaves on the same board. This
is exact: `t` is linear in the normalised opposing range, so a convex mix of
ranges has a convex mix of targets. The loss is

```
shape_error  = weighted MSE between projected shares and targets
conserve_err = (Σ ro·t_oop + Σ ri·t_ip - 1)² on the RAW sigmoid outputs
loss         = shape_error + 2 * conserve_err
```

The conservation term matters because the engine caches the **raw** shares and
evaluates them at reaches that differ from the cache-fill reach; only raw shares
that already sum to 1 stay close to conserving at other reaches.

## 4. Runtime path (`solver_daemon/src/cfr.rs`)

1. Computes exact equity once (used for warm-up and for the safety fallback).
2. Runs a short exact-equity warm-up (`max_iters/8`, clamped to 10–40 iterations).
3. Evaluates the net once per public showdown node from the warm-up average
   strategy's node-local reaches, and caches the shares
   (`fill_leaf_shares`). Evaluating from the *live* traversal reach every
   iteration makes the payoff strategy-dependent and CFR plateaus at 4–5% pot
   exploitability, so the shares are fixed per node.
4. Optionally refines (`GTO_LEAF_REFINE`, on by default) with damped refreshes
   (α=0.1, ≤15 rounds, 30-iteration CFR blocks) until the strategy and shares
   agree or the budget is exhausted.
5. Reports `leaf_mode = "leaf-net"` only if the result meets both accuracy gates.

The learned attempt has an internal budget of `min(time_limit_ms, 700 ms)` so
that the worst-case roundtrip (learned attempt + exact retry) stays under one
second.

## 5. Exact-showdown fallback

A 169-vector marginal share model cannot guarantee
`Σ reach_oop·v_oop + Σ reach_ip·v_ip = net_pot` for an arbitrary pair of
independent reaches. Only a per-pair (169×169) payoff operator can. The net
therefore approximates; the engine guards it:

```rust
// solver_daemon/src/lib.rs
fn leaf_result_passes(out, input) -> bool {
    out.converged
        && out.exploitability_pct_pot <= 0.5
        && |out.oop_ev + out.ip_ev - net_pot| <= 0.35
}
```

If a `leaf-net` solve fails either gate, `evaluate_and_solve` re-solves the same
spot with exact showdown equity and labels the result
`"exact-showdown (leaf-net fallback)"`. The reported latency includes both
attempts. `GTO_LEAF_NET=off` forces exact mode.

This makes the *returned* strategy always satisfy the published contract while
keeping the learned-path work visible and measured rather than hidden.

## 6. Measured behaviour

See `docs/ACCURACY_AUDIT.md` §9 for the current 50-board run. Summary of the
design trade-off:

- Exact-showdown: truthful, converges to < 0.5% pot, ~0.1–0.2 s, worst
  conservation gap ≈ 0.13 bb.
- Leaf-net: converges to its (approximate) game quickly, and passes both gates
  on a subset of boards; the rest fall back to exact.
- Because the equity matrix is board-only and cheap relative to tree traversal,
  the leaf net is an *accuracy/parity experiment*, not a latency optimisation.

## 7. What a fully exact learned leaf would need

A per-pair operator `E_hat[i][j]` constrained to
`E_hat[i][j] + E_hat[j][i] = 1`. Conservation is then exact for **any** reaches,
and the payoff stays board-only and linear in the opponent's reach. The natural
form is a board-conditioned, antisymmetrised low-rank factorisation
(`E_hat = 0.5 + (U S Vᵀ - V S Uᵀ)/2`). This is the recommended next step if the
leaf net is to become the default path; the current per-class marginal model is
kept because it is small, fast to evaluate and easy to audit.
